# Contract: Environment variables — common to every .NET service in production space

> Shared contract. Read only if your module's task table lists it. Do not change without the user's approval; see the contract index in the root `CLAUDE.md` for consumers.

Set by `infra` (Bicep) for production apps; set by the portal simulator for collector apps.

`AZURE_CLIENT_ID` (client id of the service's user-assigned identity, used by `DefaultAzureCredential` / `ManagedIdentityCredential`), `APPLICATIONINSIGHTS_CONNECTION_STRING`, `ASPNETCORE_URLS=http://+:8080` (HTTP services), `MOD_ENVIRONMENT` (prefix, for logs), `SQL_CONNECTION` (except where noted; Entra managed-identity connection string for database `mod`).

## Local development (outside Azure)

- Omit `AZURE_CLIENT_ID`: `DefaultAzureCredential` then uses the developer's `az login` session.
- `SQL_CONNECTION` uses `Authentication=Active Directory Default` instead of managed identity.
- Values come from git-ignored `.env.local` / `.env.<app>.local` files generated by `infra/scripts/local-env.sh`, loaded into the shell with `set -a; . ./.env.local; set +a` before `dotnet run`. Applications do not read `.env` files themselves.
- The developer's Azure permissions are granted by `up.sh --developer` (see `infra`); no keys are issued for development.
